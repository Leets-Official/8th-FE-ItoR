# Gitlog PRD

## 제품 목표와 현재 범위

Gitlog는 공개 게시물을 읽고, 로그인한 사용자가 글과 댓글을 작성·관리하는 반응형 블로그다.

## 필수 기술과 품질 기준

- Vite, TypeScript, Tailwind CSS, Axios를 사용한다. UI는 React로 구현한다.
- 서버 상태는 TanStack Query로 관리하고, Axios interceptor를 공통 HTTP 처리에 사용한다.
- `useRef`, `useMemo`, `useCallback`은 용도가 명확할 때만 사용한다. SRP·DRY·KISS를 지키며 코드의 책임을 읽기 쉽게 나눈다.
- 시맨틱 HTML, 키보드 내비게이션, 포커스 상태, 적절한 ARIA와 이미지 대체 텍스트를 제공한다.
- 이미지는 적절한 크기/포맷으로 제공하고 화면 밖 이미지는 lazy load한다. 필요한 라우트·큰 기능은 dynamic import로 분할한다.
- Lighthouse 성능·접근성·모범 사례·SEO 점수 각각 90점 이상을 목표로 한다. 실제 디자인과 API가 연결된 대표 모바일·데스크톱 페이지의 배포 빌드에서 측정하고 결과를 PR에 기록한다.

## 공통 UI

- 공통 레이아웃, 범용 UI, 기능별 컴포넌트, 페이지 조합을 목적에 따라 나눈다.
- 데이터 요청 화면은 로딩·오류·빈 결과·성공 상태를 알맞게 보여 준다. 작성·수정·삭제 작업의 성공 또는 실패도 사용자에게 알린다.
- Figma 디자인 가이드의 수치·자산·breakpoint를 기준으로 모바일과 데스크톱을 지원한다.

## 기능 요구사항 및 수용 기준

### 회원가입과 로그인

- 이메일/비밀번호 가입과 카카오 OAuth 가입을 지원한다. 이메일과 닉네임의 중복을 확인하고, 가입 중 프로필 사진을 등록할 수 있다.
- 등록한 이메일/비밀번호 또는 카카오 로그인으로 인증한다.
- 토큰 방식일 경우 refresh token으로 access token을 재발급한다. cookie 또는 storage 중 저장 방식을 API 계약과 보안 정책에 근거해 결정하고 문서화한다.
- 유효성 검사·중복·인증 실패는 입력 위치 또는 폼 수준에서 이해 가능한 메시지로 보여 준다.

### 게시물

- 비로그인 사용자도 목록과 상세 및 해당 게시물의 모든 댓글을 볼 수 있다.
- 로그인한 사용자만 글을 작성한다. 작성자 본인에게만 수정·삭제 UI와 동작을 허용한다. 서버에서도 소유권을 검증해야 한다.
- 목록은 한 페이지에 최대 10개를 보여 주며 초과 항목은 다음 페이지로 이동할 수 있다. 현재 페이지와 탐색 상태를 분명히 표시한다.
- 게시물 작성 시 텍스트와 이미지의 순서를 `contentOrder`로 보존하고 상세 화면에서 같은 순서로 렌더링한다. 필드와 자료 구조는 Swagger 계약을 따른다.

### 댓글

- 비로그인 사용자도 댓글을 읽는다. 작성은 로그인 사용자에게만 제공한다.
- 댓글 작성자 본인만 해당 댓글을 수정·삭제할 수 있다. 서버에서도 소유권을 검증해야 한다.

### 사용자와 이미지

- 로그인한 사용자는 자신의 정보를 조회하고 닉네임, 비밀번호, 프로필 사진을 변경할 수 있다.
- 이미지는 서버에서 받은 Pre-Signed URL로 업로드한다. URL 발급, 파일 업로드, 결과 등록 단계와 실패 복구는 Swagger 계약에 맞춘다.

## PR 기록 형식

매주 미션 PR에 구현 범위, 선택한 방식과 근거, 고려한 대안, 확인 방법과 결과, 미해결 항목을 남긴다. Lighthouse 목표가 해당 PR에서 측정 가능하면 사용한 페이지·환경·점수를 기록한다.

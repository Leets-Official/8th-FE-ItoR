# Conventions

파일, 이름, import/export, 타입, 주석을 추가하거나 변경할 때 적용합니다.

## 이름

- React 컴포넌트와 컴포넌트 파일은 `PascalCase`를 사용합니다.
- 함수, 변수, props는 `camelCase`를 사용합니다.
- 변경되지 않는 모듈 상수는 `UPPER_SNAKE_CASE`를 사용합니다.
- 타입과 인터페이스는 `PascalCase`를 사용하고 불필요한 `I` 접두사를 붙이지 않습니다.
- 폴더 이름은 소문자 kebab-case를 사용합니다.
- 이름은 역할과 동작을 드러내도록 작성하고 의미가 불분명한 축약어를 피합니다.
- variant는 가능한 경우 `positive`, `negative`, `previous`처럼 의미를 표현합니다.
- 디자인 명세가 버전 자체를 계약으로 사용하는 경우에만 `ver1` 같은 이름을 유지합니다.

## 파일 구성

- 한 파일은 하나의 주된 책임을 갖습니다.
- 같은 파일에서만 사용하는 작은 하위 컴포넌트와 스타일 매핑은 해당 파일 안에 둡니다.
- 독립적으로 재사용되거나 파일의 핵심 흐름을 방해할 정도로 커진 구현만 분리합니다.
- props 타입은 사용하는 컴포넌트 가까이에 둡니다.
- 단순한 variant별 스타일은 조건문을 반복하지 말고 객체 매핑으로 표현합니다.

## Import와 Export

import는 다음 순서로 작성하고 각 그룹 사이를 한 줄 띄웁니다.

1. 외부 패키지
2. `@/` 절대 경로
3. 같은 모듈의 상대 경로
4. 타입 전용 import

- 타입만 가져올 때는 `import type`을 사용합니다.
- `@/` 별칭을 사용해 상위 폴더로 올라가는 긴 상대 경로를 피합니다.
- 같은 폴더 안의 가까운 파일은 상대 경로를 사용할 수 있습니다.
- 재사용 컴포넌트와 유틸리티는 named export를 사용합니다.
- 라우트가 직접 불러오는 페이지와 레이아웃은 default export를 사용합니다.
- barrel 파일은 import 경로를 실제로 단순화할 때만 추가합니다.

## 타입과 Props

- 컴포넌트 props는 명시적인 타입으로 선언합니다.
- 서로 배타적인 props 조합은 판별 유니온으로 잘못된 사용을 타입 단계에서 막습니다.
- 선택 값은 실제로 생략 가능한 경우에만 `?`를 사용합니다.
- 이벤트 props는 `onClick`, `onChange`처럼 React 관례를 따릅니다.
- `any` 대신 구체적인 타입이나 `unknown`을 사용합니다.

## 주석

- 주석은 코드가 이미 보여주는 내용보다 의도, 제약, 선택 이유를 설명합니다.
- 내보내는 컴포넌트와 함수에는 필요할 때 간결한 JSDoc을 작성합니다.
- 반환 설명은 `@returns` 형식으로 한 줄에 작성합니다.
- props 설명은 이름만으로 의미가 충분하지 않을 때만 작성합니다.
- 전역 설정, 생성 파일, 자명한 상수에는 형식적인 주석을 강제하지 않습니다.
- 주석은 한국어로 작성하고 현재 동작과 일치하게 유지합니다.
- `TODO`에는 남은 작업과 완료 조건을 구체적으로 적습니다.
- 더 이상 유효하지 않은 주석은 코드 변경과 함께 제거합니다.

# API

Swagger API를 연결하거나 인증, 서버 상태, 이미지 업로드를 변경할 때 적용합니다.

## 계약 확인

- README의 기능 요구사항과 최신 Swagger를 함께 확인합니다.
- API 계약의 기준은 `https://blog.leets.land/swagger-ui/index.html`입니다.
- 메서드, 경로, query, request body, response와 상태 코드를 확인한 뒤 구현합니다.
- 요청·응답 필드명은 `conventions.md`의 API 이름 규칙에 따라 대소문자까지 유지합니다.
- Swagger와 실제 응답이 다르면 네트워크 응답을 확인하고 차이를 기록합니다.
- API에 없는 필드를 임의로 만들거나 응답하지 않는 값을 받은 것으로 가정하지 않습니다.
- 공통 응답의 `code`, `message`, `data` 처리는 API 경계에서 일관되게 수행합니다.

## API 계층

- Axios 인스턴스, base URL, 공통 헤더와 interceptor는 `src/shared/api`에서 관리합니다.
- 한 feature에서만 사용하는 엔드포인트 함수와 DTO는 해당 feature의 `api`에 둡니다.
- 여러 feature가 공유하는 게시글 목록 계약처럼 동일한 API 계약은 `shared/api`에서 한 번만
  선언합니다.
- Section과 표현 컴포넌트에서 Axios를 직접 호출하지 않습니다.
- 화면 모델이 필요하면 API DTO와 분리하고 명시적인 변환 함수로 만듭니다.
- 서버 상태의 캐시, 재조회, 무효화가 필요하면 TanStack Query를 사용합니다.
- 단순한 한 번의 인증 요청이나 리다이렉트에 불필요하게 Query 계층을 추가하지 않습니다.
- loading, success, error 상태를 관리하고 사용자에게 현재 결과를 UI로 보여줍니다.

## 인증

- 이메일과 카카오 OAuth 회원가입·로그인 흐름을 모두 지원합니다.
- 선택한 토큰 저장 방식을 한 곳에서 관리하고 기능마다 직접 storage에 접근하지 않습니다.
- 인증 요청에는 access token을 공통으로 전달합니다.
- access token 만료 시 refresh token으로 한 번만 재발급하고 원래 요청을 재시도합니다.
- 재발급 요청 자체에는 재발급 로직을 반복 적용하지 않습니다.
- 재발급이 실패하면 인증 정보를 정리하고 로그아웃 상태를 UI에 반영합니다.
- 이메일과 닉네임의 중복, 잘못된 입력, 미가입 계정 등 서버 오류를 해당 입력 또는 Dialog에 표시합니다.

## 권한과 기능 요구사항

- 게시물과 댓글 조회는 비로그인 사용자에게도 제공합니다.
- 게시물 작성과 댓글 작성은 로그인 사용자만 실행할 수 있습니다.
- 게시물과 댓글의 수정·삭제 UI와 요청은 작성자 본인에게만 허용합니다.
- 게시물 목록은 한 페이지에 최대 10개를 요청하고 페이지네이션 결과를 사용합니다.
- 게시물 상세 응답의 댓글을 함께 표시합니다.
- 게시물 본문의 텍스트와 이미지는 `contentOrder`와 `contentType`을 보존합니다.
- 사용자 정보 조회와 닉네임, 비밀번호, 프로필 사진 변경을 지원합니다.

## 현재 서버 계약의 제약

- 내 게시글 전용 API가 없으므로 `/posts/all/token` 결과를 현재 사용자 닉네임으로 필터링합니다.
- 게시글 생성 응답은 생성된 `postId`를 반환하지 않으므로 생성 직후 인증 목록에서 같은 제목과
  본문을 조회해 ID를 찾습니다.
- 서버가 내 게시글 API나 생성된 `postId`를 제공하면 위 우회 로직을 제거하고 응답을 직접 사용합니다.

## 이미지 업로드

- 이미지는 Pre-Signed URL 방식으로 업로드합니다.
- 업로드 URL 발급, 파일 직접 업로드, 최종 이미지 정보 전달 순서로 처리합니다.
- 이미지를 소스 코드나 API payload에 base64로 직접 포함하지 않습니다.
- 업로드 전에 이미지 MIME 형식을 검사합니다.
- 파일 크기 제한은 서버 계약에서 허용 크기를 확인한 뒤 같은 값으로 적용합니다.

## 검증

- 성공 응답뿐 아니라 비로그인, 권한 없음, 입력 오류와 서버 오류를 확인합니다.
- 인증 작업은 access token 만료와 refresh token 실패 흐름까지 확인합니다.
- 소유권이 필요한 작업은 본인과 타인 계정의 동작을 각각 확인합니다.
- 요청 URL, method, headers, query, body와 실제 response를 브라우저 Network에서 확인합니다.
- 토큰, 비밀번호, 비밀 키와 개인 정보를 코드나 로그에 남기지 않습니다.
- 변경 범위에 맞춰 `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm build`를 실행합니다.

# Architecture

프로젝트 구조를 변경하거나 라우트, 페이지, 기능 모듈을 추가할 때 적용합니다.

## 계층

- `src/app`: 앱 초기화, 전역 레이아웃, 라우터와 전역 스타일
- `src/pages`: URL 단위 화면 구성
- `src/features`: 사용자 기능 단위의 상태, 로직, 전용 UI
- `src/shared`: 여러 페이지와 기능에서 재사용하는 UI, 자산, 유틸리티

의존성은 `app → pages → features → shared` 방향을 따릅니다.

- 하위 계층은 상위 계층을 import하지 않습니다.
- `shared`는 페이지나 특정 기능의 정책을 포함하지 않습니다.
- 두 곳 이상에서 실제로 재사용되기 전에는 성급하게 공통 계층으로 옮기지 않습니다.
- 새 계층이나 폴더를 만들기 전에 기존 위치에서 책임을 표현할 수 있는지 확인합니다.

## 페이지와 기능

- 페이지는 화면의 배치와 기능 조합을 담당합니다.
- 페이지 파일에서 해당 화면의 feature 섹션과 공통 UI를 직접 조립합니다.
- 페이지 전체 UI를 그대로 대신 렌더링하는 대리 컴포넌트를 `features`에 만들지 않습니다.
- 비즈니스 규칙과 재사용 가능한 기능 로직은 `features`로 분리합니다.
- 페이지에 필요한 로직이 여러 책임을 가지면 이미지 업로드, 입력 검증처럼 기능이 드러나는
  이름의 hook으로 나눕니다.
- 공통 UI는 도메인 데이터나 라우트에 직접 의존하지 않도록 작성합니다.
- 한 파일에서만 쓰이는 작은 구현은 가까운 위치에 두고 불필요하게 파일을 늘리지 않습니다.

## 라우팅

TanStack Router의 파일 기반 라우팅을 사용합니다.

- 라우트 파일은 `src/app/routes`에 둡니다.
- URL 구조는 라우트 파일과 폴더 구조로 표현합니다.
- 라우트 파일은 페이지 연결과 라우트 메타데이터만 담당하도록 얇게 유지합니다.
- 실제 페이지 UI는 `src/pages`에 구현합니다.
- 공통 레이아웃은 루트 라우트에서 한 번만 적용합니다.
- 페이지별 헤더 차이는 `staticData.headerVariant`로 선언합니다.
- 라우터 인스턴스와 타입 확장은 `src/app/router.tsx`에서 관리합니다.
- `src/app/routeTree.gen.ts`는 자동 생성 파일이므로 직접 수정하지 않습니다.
- 동적 경로와 중첩 경로는 TanStack Router의 파일 명명 규칙을 따릅니다.

## 스타일과 반응형 구조

- 앱의 최대 너비와 전역 반응형 기준은 기존 전역 설정을 단일 출처로 사용합니다.
- 최대 너비 `1366px`와 모바일 기준 `390px 이하`를 컴포넌트에서 다시 선언하지 않습니다.
- 레이아웃에 임의의 모바일 전용 패딩이나 너비를 추가하지 않습니다.
- 기존 디자인 토큰과 공통 UI를 먼저 확인한 뒤 재사용합니다.

## 변경 원칙

- 현재 구조로 해결하기 어려운 구체적인 이유가 있을 때만 구조를 변경합니다.
- 구조 변경은 관련 import, 라우트 생성 결과, 타입 검사를 함께 확인합니다.
- 생성 파일과 사용자 작업 중인 변경 사항을 직접 덮어쓰지 않습니다.
